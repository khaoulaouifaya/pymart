Présentation générale

Pourquoi PyMart existe et comment il aide à gérer un magasin.

Le problème

Gérer un magasin à la main (produits, clients, commandes, chiffres de ventes) devient vite fastidieux et source d'erreurs. Il faut un outil simple, local, sans base de données, qui fonctionne dans un terminal.

La solution

PyMart lit des fichiers texte, nettoie et vérifie les données, gère le stock, enregistre les commandes et produit des rapports journaliers et mensuels. Tout est conservé dans un fichier JSON local.

Programmation orientée objet

Quatre classes, de l'héritage et du polymorphisme réellement utilisés.

Héritage

DigitalProduct hérite de Product : il récupère ses attributs et ses méthodes.

Polymorphisme

Les méthodes is_available et decrease_stock sont redéfinies : le service les appelle sans connaître le type du produit.

Decimal

Les montants utilisent Decimal pour éviter les erreurs d'arrondi des flottants.

models.py La classe Product : prix, stock et affichage 
class Product:
    """Un produit vendu par le magasin."""

    def __init__(self, product_id, name, price, quantity):
        self.product_id = product_id
        self.name = name
        # Decimal évite les erreurs d'arrondi des nombres flottants.
        self.price = to_decimal(price)
        self.quantity = int(quantity)

    def get_price(self):
        """Retourne le prix unitaire du produit."""
        return self.price

    def is_available(self, quantity=1):
        """Indique si la quantité demandée est disponible en stock."""
        return self.quantity >= quantity

    def decrease_stock(self, quantity):
        """Retire la quantité commandée du stock."""
        if not self.is_available(quantity):
            raise InsufficientStockError(
                f"Stock insuffisant pour {self.product_id} : "
                f"{quantity} demandé, {self.quantity} disponible."
            )
        self.quantity -= quantity

Product contient un identifiant, un nom, un prix (en Decimal) et une quantité en stock. La méthode decrease_stock lève une exception si le stock est insuffisant.

models.py DigitalProduct : héritage et polymorphisme 
class DigitalProduct(Product):
    """Produit dématérialisé : son stock est illimité.

    Cette classe hérite de Product et redéfinit plusieurs méthodes pour
    démontrer le polymorphisme.
    """

    def is_available(self, quantity=1):
        # Un produit numérique est toujours disponible.
        return True

    def decrease_stock(self, quantity):
        # Pas de stock à décrémenter pour un produit numérique.
        pass

    def display(self):
        return (
            f"{self.product_id} - {self.name} - {self.price:.2f} €"
            f" - Produit dématérialisé (stock illimité)"
        )

Le même appel decrease_stock(quantity) ne fait rien pour un produit numérique : c'est le polymorphisme en action.

models.py La classe Order et le calcul du montant 
class Order:
    """Une commande passée par un client."""

    def __init__(self, order_id, customer_id, product_id, quantity,
                 order_date, unit_price):
        self.order_id = order_id
        self.customer_id = customer_id
        self.product_id = product_id
        self.quantity = int(quantity)
        self.order_date = order_date  # objet datetime.date
        # Prix unitaire figé au moment de la commande (Decimal).
        self.unit_price = to_decimal(unit_price)

    def total(self):
        """Calcule le montant total de la commande."""
        return (self.unit_price * self.quantity).quantize(
            Decimal("0.01"), rounding=ROUND_HALF_UP
        )

total() calcule prix × quantité et arrondit à deux décimales avec ROUND_HALF_UP. Le prix est figé au moment de la commande.

Importation et validation

Les fichiers sont nettoyés (strip, split, upper) puis chaque enregistrement est validé. Une ligne invalide est signalée sans bloquer les autres.

parsers.py Séparateurs et messages d'erreur 
def _split_columns(line):
    """Découpe une ligne avec le bon séparateur.

    Le séparateur normal est « ; ». Si la ligne utilise « | », on l'accepte
    aussi car la correction est possible sans ambiguïté.
    """
    if ";" in line:
        return [column.strip() for column in line.split(";")]
    if "|" in line:
        return [column.strip() for column in line.split("|")]
    return [line.strip()]


def _error(file_path, line_number, message):
    """Construit un message d'erreur avec le fichier et le numéro de ligne."""
    return f"{file_path}, ligne {line_number} : {message}"

strip() supprime les espaces inutiles, split() découpe la ligne. Le séparateur | est accepté en secours lorsque la correction est sans ambiguïté.

parsers.py Validation du prix et de la quantité 
        try:
            price = to_decimal(price_text)
        except Exception:
            errors.append(_error(
                file_path, line_number,
                f"prix invalide : {price_text!r}"
            ))
            continue
        if price < 0:
            errors.append(_error(
                file_path, line_number,
                f"prix négatif : {price_text}"
            ))
            continue

        try:
            quantity = int(quantity_text)
        except ValueError:
            errors.append(_error(
                file_path, line_number,
                f"quantité invalide : {quantity_text!r}"
            ))
            continue
        if quantity < 0:
            errors.append(_error(
                file_path, line_number,
                f"quantité négative : {quantity_text}"
            ))
            continue

Prix invalides, prix négatifs, quantités invalides ou négatives : chaque cas est détecté, un message précis est ajouté, puis on passe à la ligne suivante avec continue.

Sont aussi validés : identifiants mal formés, doublons, dates invalides (date.fromisoformat) et références vers des produits ou clients inexistants.

Exceptions personnalisées

Des erreurs claires, toutes regroupées sous une classe de base.

exceptions.py La hiérarchie des erreurs 
class PyMartError(Exception):
    """Classe de base pour toutes les erreurs de PyMart."""


class DataValidationError(PyMartError):
    """Donnée invalide (prix, quantité, identifiant, etc.)."""


class UnknownProductError(PyMartError):
    """Référence à un produit inexistant."""


class UnknownCustomerError(PyMartError):
    """Référence à un client inexistant."""


class DuplicateIdError(PyMartError):
    """Identifiant déjà présent (doublon)."""


class InsufficientStockError(PyMartError):
    """Stock insuffisant pour honorer une commande."""

Toutes les exceptions héritent de PyMartError : on peut les attraper d'un seul coup dans l'interface en ligne de commande.

services.py Levée des exceptions dans OrderService 
    def create_order(self, customer_id, product_id, quantity, order_date=None):
        """Crée une commande après toutes les vérifications."""
        customer_id = customer_id.upper()
        product_id = product_id.upper()

        if customer_id not in self.customers:
            raise UnknownCustomerError(f"Client inconnu : {customer_id}")
        if product_id not in self.products:
            raise UnknownProductError(f"Produit inconnu : {product_id}")

        if not isinstance(quantity, int) or quantity <= 0:
            raise DataValidationError("La quantité doit être un entier positif.")

        product = self.products[product_id]
        if not product.is_available(quantity):
            raise InsufficientStockError(
                f"Stock insuffisant pour {product_id} : "
                f"{quantity} demandé, {product.quantity} disponible."
            )

Chaque erreur produit un message compréhensible. Dans la CLI, un try / except PyMartError affiche le message sans faire planter le programme.

Générateurs

Un générateur yield réellement utilisé par tous les parseurs.

parsers.py read_lines : lecture ligne par ligne avec yield 
def read_lines(file_path):
    """Générateur qui lit un fichier ligne par ligne.

    Utilité : pour de gros fichiers, on ne charge qu'une ligne à la fois en
    mémoire au lieu du fichier entier. On ignore les lignes vides et les
    commentaires (lignes qui commencent par #).
    """
    with open(file_path, "r", encoding="utf-8") as fichier:
        for line_number, raw_line in enumerate(fichier, start=1):
            line = raw_line.strip()
            if not line or line.startswith("#"):
                continue
            yield line_number, line

Grâce à yield, la fonction ne charge qu'une ligne à la fois en mémoire. Elle est utilisée par parse_products, parse_customers et parse_orders.

Tests

30 tests unitaires avec unittest, sans dépendance externe.

tests/test_models.py Tester le polymorphisme 
    def test_polymorphism(self):
        physical = Product("P001", "Laptop", "10.00", 1)
        digital = DigitalProduct("P006", "Ebook", "24.99", 0)
        # Même appel, comportement différent : c'est le polymorphisme.
        self.assertFalse(physical.is_available(5))
        self.assertTrue(digital.is_available(1000))
        physical.decrease_stock(1)
        digital.decrease_stock(1000)  # ne change rien
        self.assertEqual(physical.quantity, 0)
        self.assertEqual(digital.quantity, 0)

Le test vérifie qu'un produit physique limite son stock alors qu'un produit numérique est toujours disponible.
